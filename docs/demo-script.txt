=====================================================
0:00 - 0:25  THE HOOK  (25s)
=====================================================
Say:
  "Comic artists and indie game devs have a problem: they need the same
   character to look the same across dozens of images. Text-to-image is
   stateless — same prompt, different face, every single time.

   The industry's answer is to train a LoRA per character: 15+ images, a GPU
   training run, a model file for every character. It works. It's expensive.

   I asked a narrower question: how much consistency can you get from MEMORY
   alone? No training. No reference images. No model files."

Show: the app, already open. Don't click yet.

DO NOT say: "it's a wrapper around ComfyUI." It isn't, and you have 2 minutes
to prove that.


=====================================================
0:25 - 1:15  THE PROOF: A/B COMPARE  (50s)  <-- YOUR STRONGEST MOMENT
=====================================================
RECORDING PATH: pre-generated pair (default — no live run, see RECORDING MODE).

Do:
  1. Alt-tab to the pair1 images already open side by side
     (full-screen viewer, OFF on the left, ON on the right)
  2. (Optional, shows the UI) come back to the Gallery and open the compare
     pair at seed 150634584270736 — both arms list their final prompts

Say:
  "This ran the same prompt twice with ONE shared seed and the same size.
   The only difference between these two images is whether memory is on."

When both images are on screen, point at the LEFT then the RIGHT:
  "Memory OFF — generic figure, dark hair, dark shirt. It has no idea who Kai is.
   Memory ON — blue hair, red jacket, ripped jeans, crouched stance. That's the
   character I stored in memory.

   Same seed. Same prompt. Same size. The only variable was memory."

Then say the numbers:
  "I didn't just eyeball it. I ran this 20 times. Memory recall: 20 out of 20.
   Mean pixel divergence: 15 percent, standard deviation 2.3 points.
   The effect shows up in every single run."

LIVE VERSION (only if a judge asks — never volunteer it):
A/B Compare tab, prompt "Kai skateboarding at sunset", Run comparison.
It takes ~2 minutes for the pair. Answer in docs/qa-cheat-sheet.txt.


=====================================================
1:15 - 1:55  IT'S NOT A WRAPPER: MEMORY TAB  (40s)
=====================================================
Do:
  1. Click "Memory" tab
  2. Expand the Kai entry
  3. Scroll to "version history"

Say:
  "This is every memory the studio holds — content, tags, importance, trust
   score, how many times it's been recalled.

   And here's version history. When you edit a character, it doesn't
   delete-and-recreate. It supersedes — the old version is marked historical
   and stays queryable. v1, v2, current."

Point at the pipeline:
  "The whole thing is a pipeline: recall memories, build an enriched prompt,
   send it to Qwen Image through ComfyUI, get feedback, write it back.
   The workflow file is introspected at runtime — I never hardcode node IDs."

(Difficulty / war-story answers — CFG 1, 8-step schedule — live in
docs/qa-cheat-sheet.txt. Q&A only. Do not say them in the video.)


=====================================================
1:55 - 2:30  THE TWIST: QUARANTINE  (35s)
=====================================================
Do:
  1. Click "Gallery"
  2. Pick any image, click "+ note"
  3. Type: too dark and muddy
  4. Submit (thumbs down)

Say:
  "Feedback teaches. That note just became a learned 'avoid' trait."

Then:
  5. On another image, "+ note", type: hair color is wrong
  6. Submit

Say, and land this:
  "But that one did NOT go into memory. It went to quarantine.

   Because 'hair color is wrong' is a complaint about one character, not a
   general preference. If I'd stored it automatically, every future prompt
   would carry the phrase 'free of hair color is wrong.' Meaningless.

   Most feedback systems write straight to memory. Refusing to trust
   identity-level feedback is what keeps this one clean."

FALLBACK: if the Quarantine tab has items pending already, just show those
instead of creating new ones. Say "here's one that was held back."


=====================================================
2:30 - 2:50  IMPACT + CLOSE  (20s)
=====================================================
Say:
  "Who cares? A comic artist with a recurring cast. An indie dev who needs one
   protagonist across a whole game. It's local, it's free, there are no paid
   APIs, and memory survives restarts.

   Next: semantic recall so memory surfaces things you never named, and
   image-reference memory so a character can carry an actual face.

   It's Banana Hacks 2026. StyleMemory. Thank you."

STOP TALKING. Let them ask.
